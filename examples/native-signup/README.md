# Embedded signup reference

This example supplies handlers for an application's own signup, sign-in and account-settings screens. It creates no Soran widget, user database, custodial wallet or hidden transaction. This example requires Holder 0.5.0 and Lookup 0.7.0 with the matching native-claim successor Registry/Lookup. The namespace owner must enable the desired public claim policy; simply connecting a wallet does not enable registration.

Construct `SoranHolder` with the linked classic G wallet's `TxSigner`, `registryId`, `rpcUrl` and `passphrase`; construct `Soran` with the matching Registry and Universal Lookup. Pass both to `SignupNames`. The app owns its UI and implements `RecoveryStore` for public intent/hash references. Never store a wallet secret or eligibility signing credential there.

1. Authenticate the private app account and associate its wallet using fresh account authentication plus a purpose-bound, single-use wallet proof. The app backend derives the account from its session; a client-supplied account ID is not a membership proof.
2. An explicit Choose username action calls `review`. Display the exact username, full G/M/C receiving destination, G memo if any, namespace policy and fee in XLM. A fee-free username still has network/storage costs. The top-level namespace's 5000 XLM fee is unrelated.
3. Open claims need no backend approval. A complete committed allowlist uses the user's proof. For optional app-approved claims, `buildClaim` returns the exact unsigned admission entry. The backend independently reads/pins the deployment, owner epoch and policy, verifies membership/wallet binding, then uses `signClaimEligibility`. It signs an admission entry, never an owner transaction. The user's wallet separately authorizes the complete claim.
4. The explicit confirmation button calls `submit`. The example journals before wallet signing, so a cancellation may also leave an unresolved draft. Show distinct Cancelled before broadcast, Unknown, Failed on chain, Confirmed, and Confirmed but verification unavailable states. If the sign-only wallet adapter positively proves rejection before any signature was produced, supply its strict `isUnsignedWalletDismissal` classifier. The example then compare-and-clears that exact hash while retaining the same immutable intent for another user-approved attempt; generic errors/timeouts never take this path. Clear/recreate a request only after receipt/transaction reconciliation proves no original effect can still occur. A null receipt or empty local history is insufficient proof. This example deliberately supplies no blind-retry button.
5. `resume` recovers the same immutable request after sign-in/reload. After verified completion, call `finalizeCompleted`: `RecoveryStore.archiveAndClear` must atomically retain the verified receipt and clear only the matching pending intent, so a newer operation is never erased and future choices are not blocked forever. A historical receipt is not proof of current ownership: verify current Universal Lookup metadata before linking the name to the account. Routine later sign-in never calls `review`/`submit` automatically, and logout never relinquishes the name.

G without memo, G with ID/Text/Hash, full muxed M (memo none), and C (memo none) are payment destinations. Current signing adapters use a G claimant; M is not a separate signing identity. Preserve the returned memo or muxed ID. `holder.setPayment`, transfer and permitted renewal remain independent of new-member approval. Names are transferable assets: transferring a name must not transfer an old private app account or its data.

`prepareAdmission` is for approval mode and does not currently accept allowlist proof input; an allowlist UI calls `holder.buildClaim(intent,{proof})` directly. The example does not implement a wallet adapter, application membership service, cross-device recovery discovery, receipt keeper, mobile handoff, fee sponsorship or a production recovery dashboard. Those remain application responsibilities and release tests, not implied capabilities of this reference.

Install and check this reference with `npm ci`, `npm run typecheck` and `npm test` in this directory. It imports the public package names and requires one Stellar SDK17 runtime, without monorepo aliases. The included fixture is public deterministic test data, not an account credential.
